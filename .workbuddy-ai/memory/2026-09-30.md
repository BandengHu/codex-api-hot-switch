# 2026-09-30

## Tauri 版 0.2.12：路径 bug 修复 + 中文安装界面（已提交 6698c9a，分支 tauri/experiment）

### ① 路径 bug 根因（用户实测报错）
`找不到 server.js：\\?\C:\Users\Administrator\AppData\Local\Codex SwitchGate\server`

追到 `tauri-utils-2.10.0/src/platform.rs` 的 `resource_dir_from()`：
**只有 linux / macOS / iOS 三个分支，Windows 走 `cfg!(target_os="windows")` 唯一分支，无条件 `return Ok(exe_dir)`**。
即 `resource_dir()` 在 Windows = exe 同级目录。
而 `bundle.resources = ["resources/server/**/*"]` 安装后会**原样保留 `resources\` 那一层**
→ 真实位置是 `<install>\resources\server\server.js`，原代码只 `join("server")` 所以找不到。

**修复**：候选数组 `[res/resources/server, res/server]`，逐个查 `server.js` 存在性；
全失败时错误信息列出两个尝试路径。

### ② 中文安装界面
- 字段是 `bundle.windows.nsis.languages`，值用 **NSIS 语言代码** `"SimpChinese"`。
- tauri-bundler 2.10.0 内置 `.../windows/nsis/languages/SimpChinese.nsh`（官方完整译文：
  addOrReinstall / alreadyInstalled / chooseMainHowToInstall / createDesktop / uninstallApp…），**不用自己写翻译**。
- `displayLanguageSelector: false` → 直接中文，不弹语言选择框。
- 验证方法：看生成的 `target/release/nsis/x64/installer.nsi` 第 464-467 行
  `!insertmacro MUI_LANGUAGE "SimpChinese"` + `!include "...\SimpChinese.nsh"`。

### ③ NsisConfig 踩坑（连续错两次）
- `NsisConfig` 是 **`deny_unknown_fields`**：任何未知字段让整个对象校验失败，报错只含糊说
  `not valid under any of the schemas listed in the 'anyOf' keyword`，**不指出具体字段**。
  → 改动前先用 `tauri-cli-2.12.0/config.schema.json` 的 `definitions.NsisConfig` 预校验。
- **`compression` 合法值是全小写 `zlib`/`bzip2`/`lzma`/`none`**；PascalCase 的 `"Lzma"` 是非法值
  （我曾误以为要改成 PascalCase，反而更错）。
- `NsisConfig` 合法字段全集：`template` / `headerImage` / `sidebarImage` / `installerIcon` /
  `uninstallerIcon` / `uninstallerHeaderImage` / `installMode` / `languages` / `customLanguageFiles` /
  `displayLanguageSelector` / `compression` / `startMenuFolder` / `installerHooks` / `minimumWebview2Version`。
  **没有 `shortcutName`**（正确字段是 `startMenuFolder`）。

### ④ 新增诊断能力（GUI 无控制台 → 落盘是唯一稳定手段）
- `guide_log(level, message)` 命令 → `logs/guide.log`（引导页各状态节点写日志）
- `debug_paths()` 命令 → JSON：`resourceDir` / `serverRoot` / `serverJsExists` / `exeDir` / `dataDir` / `debugBuild`
- `boot.log` 启动痕迹（`run()` 进函数即写一行 pid + exe + data_dir）→ 定位静默退出死在哪步
- `probe_node_version` 加 **4 秒超时轮询**（原 `Command::output()` 无超时，候选 node 挂网络盘会永久卡住）
- `setup()` 里托盘创建失败**不再 panic**（原 `.expect("创建托盘失败")`），改记 `tauri-shell.log` 继续跑

### ⑤ 体积再降：8.74MB → 4.98MB
- 删 `vendor/.pnpm`（`prunePnpmStore`）。依据：Next standalone 已把依赖 bundle 进 `.next/server/chunks`；
  实测移走后 **16 个 API 路由全 200/405、0 个 5xx**，日志出现
  `ExperimentalWarning: SQLite is an experimental feature` 证明 `node:sqlite` 真被加载。
- 新增 `assertNoLongPaths(root, limit=250)` 护栏：pnpm 把 peer 校验和嵌进目录名
  （`.pnpm/next@16.2.6_@babel+core@7.2_40a7effce8bcad24669d45809ebe449e`），
  实测 **146 个条目**绝对路径超 Windows 260 上限（最长 **291**）→ `makensis` 打不开文件即整体 abort。
- **注意 `pruneVendor` 顺序**：先 `pruneDuplicatedTopLevelVendorPackages`（依赖 `.pnpm` 存在），
  再 `prunePnpmStore`。顺序反了会把去重依据删掉。
